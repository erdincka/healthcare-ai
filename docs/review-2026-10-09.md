# HealthcareAI review, 2026-10-09

Scope: full review of the application, its Helm chart and its deployment on the `dlgpcai`
HPE Private Cloud AI cluster, the TriageAI JSON failure, and recommendations. Findings were
verified against the running cluster, the Ollama server and the code; nothing below is assumed.

## 1. How the app was actually running

| Item | Finding |
|---|---|
| EzAppConfig | `healthcareai-0.2.0-…` existed (status ready, `healthState: unknown`), but its Helm release `healthcareai` had lost its Deployment, Service and VirtualService. Only the PVC and release secret remained. |
| Live pod | A **Tilt** development release named `healthcare-ai` (image `registry.<domain>/healthcare-ai:tilt-…`, 94 days old) served `https://healthcare.<domain>`. Its VirtualService had been hand-edited in Lens (host changed, `tls` block removed), which `tilt up` would have reverted. |
| Why `healthState: unknown` | The platform looks for pods labelled `hpe-ezua/app: healthcareai`; the Tilt pods carried `hpe-ezua/app: healthcare-ai`. |
| Settings | MedGemma pointed at `medgemma-json:latest`, a model that no longer existed on Ollama. |
| Kyverno | No ClusterPolicy or Policy targets the `healthcareai` namespace. The `add-vendor-app-labels-*` policies seen for other apps are Helm pre-install hooks inside those charts. This chart labels pods itself through `_hpe-ezua.tpl`, so nothing had to be removed. Platform policies that do touch the pod: scheduler assignment for `vendor-service` pods, CA-bundle injection, host-path and MLIS PVC validations (all passing). |

## 2. TriageAI root cause

`medgemma1.5:4b` on Ollama 0.33.3 is the official library build with the plain Gemma template
and no thinking support. The model nevertheless reasons before answering, as plain text:
`<unused94> thought … <unused95>` followed by fenced JSON. With `max_tokens: 1024` the reasoning
consumed the budget (`finish_reason: length`), so the JSON was truncated as well.

Tested against the live server with the app's exact prompt:

| Variant | Result |
|---|---|
| As the app sent it | thought block, truncated JSON, 35 s |
| Native `/api/chat` with `think: false` | no effect (template cannot switch thinking off) |
| OpenAI-compatible + `response_format` `json_schema` | pure JSON, 363 tokens, about 10 s |
| OpenAI-compatible + `think: false` field | no effect |
| OpenAI-compatible + `response_format` `json_object` | pure JSON, about 10 s |

Fix applied: request `response_format` with a JSON schema (Ollama maps it to grammar-constrained
decoding; vLLM supports the same field), raise `max_tokens` to 2048, reject `finish_reason:
length`, and as a safety net strip reasoning blocks, extract the first balanced JSON object and
validate it with a Pydantic model before saving. The model and Ollama were not changed.

## 4. Decisions recorded

- The Settings tab stays open to every visitor so that demo users can switch models and
  databases. The app must not be used with real patient data.
- The EzAppConfig import is the real deployment; Tilt is for development and testing only.
- MedGemma is served by Ollama as `medgemma1.5:4b`; the model and Ollama settings are not modified.

## 5. Recommendations not done in this pass (prioritised)

1. **TLS verification.** Every call uses `verify=False`; the pod already has the platform CA
   bundle mounted via `SSL_CERT_FILE`, so verification can simply be enabled.
2. **Connection reuse.** An asyncpg pool and a shared `httpx.AsyncClient`; timeouts as constants.
3. **HPE branding.** Apply the HPE theme to Gradio and do an en_GB copy pass; split the 600-line
   `create_interface()` into per-tab builders.
4. **Dependency management.** Move to `pyproject` + `uv.lock` with `uv sync` in the Dockerfile;
   add pre-commit and a CI workflow (ruff, mypy, pytest, helm lint). The GitHub remote has no CI,
   so run the full suite before every push.
5. **Schema.** Severity CHECK constraint, index on `visit_time`; Alembic if the schema grows.
6. **Repository hygiene.** Remove the tracked Superset zip and the 2.9 MB deck from git; refresh
   `superset/readme.txt`, which mentions a deleted populate script.
7. **Other demo charts.** Consider replacing their `add-vendor-app-labels-*` Kyverno hooks with
   labels in the templates, as this chart does.
